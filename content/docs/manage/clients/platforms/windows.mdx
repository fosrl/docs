## Install

- [Pangolin for Windows Installer](https://pangolin.net/downloads/windows) - This is the official page to download the latest installer file for Windows.
- [All Versions](https://github.com/fosrl/windows-linux/releases) - The releases section of this repository contains release notes and download artifacts for the latest version and all older versions.

### Installation Steps

1. **Download and install the Pangolin client**

   Download and install the Pangolin client using the official .msi installer from the download button above.

2. **Launch Pangolin**

   Open Pangolin from the Start menu or the shortcut on your Desktop.

3. **Log in with your Pangolin account**

   Log in on your Pangolin Cloud account or your self-hosted Pangolin instance.

   - Click the Pangolin icon in the task bar's system tray and select Log in.

## Companion Mode

Companion mode lets [Pangolin CLI](/manage/clients/platforms/cli) use this app's login and tunnel. Sign in and connect here, then run CLI commands as that same account. You do not run `pangolin login` again.

Companion mode requires Pangolin for Windows 0.11.0 or later, and it is on by default once the CLI is installed. It is also available on [macOS](/manage/clients/platforms/mac#companion-mode) and [Linux](/manage/clients/platforms/linux#companion-mode).

1. Log in with the Windows client and connect.
2. Install Pangolin CLI if it is not already installed. From the Pangolin system tray menu, choose **More** > **Install Pangolin CLI…**, or follow the [CLI install steps](/manage/clients/platforms/cli).
3. Run CLI commands in a terminal. For example, open SSH to a [private SSH resource](/manage/resources/private/ssh):

```bash
pangolin ssh username@alias
```

The CLI follows the account, organization, and exit node selected in the desktop app. Change those in the app. While companion mode is on, `pangolin login`, `pangolin logout`, and `pangolin select` for account, organization, or exit node are blocked.

The desktop app has to be open and logged in. If it is not, the CLI asks you to start Pangolin and log in.

Commands to check status or turn companion mode off are on the [CLI companion mode section](/manage/clients/platforms/cli#companion-mode).

## Configure

<Note>
This section covers the general settings for this platform. DNS, MTU, and other connection settings are the same on every platform and are on [Platforms](/manage/clients/platforms#connection-settings).
</Note>

### Start at Login

When enabled, Pangolin starts when you sign in to Windows.

### Connect at Start

When enabled, the tunnel connects whenever Pangolin starts. This also opens Pangolin at sign-in.

### Automatically Download and Install Updates

When enabled, Pangolin downloads updates in the background and installs them the next time Pangolin quits or starts. See [Automatic Updates](#automatic-updates).

### Config File

On Windows, the Pangolin GUI reads configuration from two `pangolin.json` files:

- User config: `%LOCALAPPDATA%\Pangolin\pangolin.json` (for example, `C:\Users\USER\AppData\Local\Pangolin\pangolin.json`)
- System config: `%ProgramData%\Pangolin\pangolin.json`, for every user of the computer

Most keys in the `Config` object below can be set in either file. If the same key is in both, the user config's value is used, so administrators can set defaults in the system config while each user can still change their own. Keys marked **System config only** must be set in `%ProgramData%\Pangolin\pangolin.json`; restart the Pangolin manager service and Pangolin after changing them. See [Which Setting Applies](#which-setting-applies) for how the two files combine with per-organization settings and server-side client settings.

As a system administrator, you can script placing `pangolin.json` in `%ProgramData%\Pangolin\` to set defaults for every user, and/or in each user's `%LOCALAPPDATA%\Pangolin\` folder for per-user settings.

### Per-Organization Settings

The top-level keys above are settings for **all organizations**. The connection settings can also be set for one organization, in the `orgs` object. Each key in `orgs` is an organization ID. Its value can hold any key marked **Can be set per organization** above, with the same meaning.

It can also hold `exitNodeResourceId` (integer): the exit node to use in this organization until the user picks one in the app. Exit nodes only exist within one organization, so this key has no top-level equivalent.

A key the organization's entry leaves out falls back to the top-level key, so an entry only needs the settings that differ. Keys marked **System config only**, and the other app and update settings, can't be set per organization.

The app writes the user config. In **Settings** > **Connection**, an organization uses the settings for all organizations until the user selects **Use Own Settings**. That copies every connection setting into the organization's entry in `orgs`, so nothing changes until they're edited, and later changes on that screen are saved only for that organization. **Reset** removes them again.

### Which Setting Applies

The system config and the user config have the same format, including `orgs`. When the client connects to an organization, it uses each connection setting from the first place that sets it:

1. [Server-side client settings](/manage/clients/server-side-settings) for the user's role in the organization. These always apply: nothing in either `pangolin.json` or the app can change a setting the server manages.
2. The organization's entry in `orgs` in the user config.
3. The organization's entry in `orgs` in the system config.
4. The top-level key in the user config.
5. The top-level key in the system config.
6. The built-in default.

The two files are combined key by key first, with the user config winning, and only then is the organization's entry checked before the top-level keys. So an organization's entry beats a top-level key no matter which file each is in:

- A user's top-level setting does **not** replace an administrator's `orgs` entry in the system config. That organization keeps the administrator's value, and the user's setting applies to every other organization.
- A user's value for the same key in the same organization's entry **does** replace the administrator's.

For example, with this system config at `%ProgramData%\Pangolin\pangolin.json`:

```json
{
  "primaryDNS": "1.1.1.1",
  "mtu": 1400,
  "orgs": {
    "acme": {
      "primaryDNS": "10.0.0.53"
    }
  }
}
```

and this user config at `%LOCALAPPDATA%\Pangolin\pangolin.json`:

```json
{
  "primaryDNS": "9.9.9.9",
  "orgs": {
    "acme": {
      "mtu": 1280
    }
  }
}
```

the user's organizations use `9.9.9.9` and MTU `1400`, except `acme`, which uses `10.0.0.53` (the administrator's entry for it beats the user's top-level server) and MTU `1280` (the user's entry for it beats the system config's top-level MTU). If the role's server-side client settings manage the upstream DNS servers or the MTU, those values replace all of these.

<Tip>
    To keep users from changing a setting, manage it with [server-side client
    settings](/manage/clients/server-side-settings), or set `userSettingsDisabled`
    in the system config. Values in the system config alone are defaults that a
    user's own settings can replace.
</Tip>

After editing the system config, restart the Pangolin manager service and Pangolin.

## Update

### Automatic Updates

The Windows client checks for updates automatically in the background. When a new version is available, Pangolin shows a notification and adds **Pangolin Update Available…** to the system tray menu. Open the notification or that menu item to see a dialog asking whether to install the update now.

**Install Update** downloads the new version and installs it. Pangolin restarts when the installation finishes, and the tunnel disconnects briefly while that happens. **Later** closes the dialog and leaves the current version in place.

You can also check from the system tray: **More** > **Check for Updates…**.

Automatic installation can be turned on with the **Automatically Download and Install Updates** setting, or by setting `autoDownloadUpdatesEnabled` to `true` in the [config file](#config-file). Pangolin then downloads the update in the background while you keep using the current version, without a notification. The update installs:

- **When you quit Pangolin** from the system tray. Pangolin stays closed afterwards.
- **When Pangolin starts**, including at sign-in. 
- **When Windows starts**, before Pangolin opens, if the setting is on in the system config.

The tunnel disconnects while the update installs. If Pangolin stays open for about a week with an update already downloaded, it asks you to install that update. You can also install it at any time from **Pangolin Update Available…** in the system tray menu.

### Manual Updates

Find the latest version in the [GitHub releases](https://github.com/fosrl/windows-linux/releases).

You can download the latest installer and run it again to install the latest version. Visit [https://pangolin.net/downloads](https://pangolin.net/downloads) for the official installer.

## Uninstall

1. Quit Pangolin from the system tray if it is running.
2. Open **Settings** > **Apps** > **Installed apps**, find **Pangolin**, and select **Uninstall**. Tip: search for "Add or Remove Programs" to find the uninstall option.

The MSI removes the app, the Pangolin Manager service, and Start Menu / Desktop shortcuts. It does not always delete the user or system config. To clear those as well:

```powershell
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\Pangolin"
Remove-Item -Recurse -Force "$env:PROGRAMDATA\Pangolin"
```

If you also installed [Pangolin CLI](/manage/clients/platforms/cli), uninstall it separately. See [Uninstall Pangolin CLI](/manage/clients/platforms/uninstall-cli).
